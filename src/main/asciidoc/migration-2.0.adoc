= Migrating to 2.0

== Baseline

Java 17 is required; stay on 1.x for Java 6–16.

== Removed integrations

The taglib, JNDI, servlet and Spring support classes are removed. Replacements:

* Servlet / interceptor query counting (`*QueryCountLoggingServletFilter`, `*QueryCountLoggingRequestListener`,
  `*QueryCountLoggingHandlerInterceptor`, `QueryCounterClear*`): call `QueryCounter.start()` around the request (Phase 3).
* Taglib (`<dsp:metrics/>`): no replacement.
* JNDI (`ProxyDataSourceObjectFactory`): construct the datasource with `ProxyDataSourceBuilder`.
* Spring XML (`ProxyConfigSpringXmlSupport`, `ProxyConnectionAdvice`, `BeanNameProxyDataSource`,
  `DataSourceProxyNativeJdbcExtractor`): use Java config with `ProxyDataSourceBuilder`.

== Listeners

* `ProxyConfig.Builder.queryListener(...)` and `methodListener(...)` are replaced by
  `ProxyConfig.Builder.listener(ProxyDataSourceListener)`, which can be called repeatedly and appends.
* `ProxyConfig.getQueryListener()` and `getMethodListener()` are replaced by `ProxyConfig.getListener()`.
* `MethodExecutionContext.getElapsedTime()`, `setElapsedTime` and `MethodExecutionContext.Builder.elapsedTime` now use
  `java.time.Duration` instead of `long`.
* `ExecutionInfo.getElapsedTime()` (`long`, milliseconds by default) becomes `QueryExecutionContext.getElapsedTime()`
  (`Duration`). The 1.x unit depended on the stopwatch factory (nanoseconds with `NanoTimeStopwatchFactory`);
  a `Duration` carries its unit.
* Custom `Stopwatch` / `StopwatchFactory` implementations must return a `Duration` from `Stopwatch.getElapsedTime()`.
* If `afterMethod` throws while the JDBC call itself failed, the listener's exception is added to the JDBC exception
  with `addSuppressed` and the JDBC exception is rethrown. In 1.x the listener's exception replaced it.
* `QueryExecutionListener` and `MethodExecutionListener` are removed. Implement `ProxyDataSourceListener`:
  `beforeQuery(ExecutionInfo, List<QueryInfo>)` becomes `beforeQuery(QueryExecutionContext)` (queries via
  `context.getQueries()`), and `beforeMethod` / `afterMethod` keep their `MethodExecutionContext` signature.
  One class can implement both query and method callbacks.
* `ChainListener` / `CompositeMethodListener` are removed: register several listeners on the builder
  (`listener(a).listener(b)`); they run in registration order.
* `NoOpQueryExecutionListener`, `NoOpMethodExecutionListener` and `JdbcLifecycleEventListenerAdapter` are removed:
  implement `ProxyDataSourceListener` (or `JdbcLifecycleEventListener`) and override only what you need; every
  callback has a no-op default.
* Lifecycle listeners: register with `listener(JdbcLifecycleEventListener.asListener(myLifecycle))`.
  `JdbcLifecycleEventListener.beforeQuery` / `afterQuery` now take a `QueryExecutionContext`.
* `ProxyDataSource.addListener(...)` and the deprecated `setListener(...)` take a `ProxyDataSourceListener`
  instead of a `QueryExecutionListener`.
* Built-in listeners (`DataSourceQueryCountListener`, `SlowQueryListener`, the query-logging and slow-query-logging
  listeners, `TracingMethodListener`) now implement `ProxyDataSourceListener`. Subclass hooks change accordingly:
  `SlowQueryListener.onSlowQuery(QueryExecutionContext, long)`, `getExecutionInfoKey(QueryExecutionContext)`;
  `QueryLogEntryCreator.getLogEntry(QueryExecutionContext, boolean, boolean, boolean)`;
  `LoggingFilter.shouldLog(QueryExecutionContext)`; the `DefaultQueryLogEntryCreator` / `DefaultJsonQueryLogEntryCreator`
  `write*Entry(StringBuilder, QueryExecutionContext)` hooks. (Phases 3 and 4 replace these classes.)
* Query log `Time:` and the query-count elapsed time are always milliseconds. In 1.x they were nanoseconds when
  `NanoTimeStopwatchFactory` was configured. `TracingMethodListener` keeps the 1.x unit.

`ProxyDataSourceBuilder` listener registration:

[cols="2,3"]
|===
|1.x |2.0

|`listener(QueryExecutionListener)`, `methodListener(MethodExecutionListener)` (removed)
|`listener(ProxyDataSourceListener)`. All registrations run in call order.

|`listener(JdbcLifecycleEventListener)` (removed)
|`listener(JdbcLifecycleEventListener.asListener(myLifecycle))`

|`beforeQuery((execInfo, queries) -> ...)` / `afterQuery(...)` (`SingleQueryExecution`)
|`beforeQuery(ctx -> ... ctx.getQueries() ...)` / `afterQuery(...)` taking `Consumer<QueryExecutionContext>`

|`beforeMethod(...)` / `afterMethod(...)` (`SingleMethodExecution`)
|Same names, taking `Consumer<MethodExecutionContext>`; `SingleQueryExecution` and `SingleMethodExecution` are removed.

|`ExecutionInfo`
|`QueryExecutionContext`; `getElapsedTime()` is now a `Duration`.
|===
